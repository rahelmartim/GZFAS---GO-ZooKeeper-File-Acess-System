        How ZooKeeper keeps the order

        Locks

        Each request creates an ephemeral sequential znode, such as locks/read-0000000004. A writer waits for the znode right before its own. A reader waits only for the last writer before it, so many readers share a file. Each waiter watches one znode, so a release wakes one client.

        Crashes

        Every client has its own session. When a client disconnects or crashes, its session ends, and ZooKeeper deletes its ephemeral znodes: its client znode and its locks. The next client in each queue gets the lock.

        Versions

        Every write adds a sequential znode under versions/. The file znode then changes with a version check (set -v), so no update is lost. The content itself lives outside ZooKeeper.

        Leader

        Servers create servers/n- znodes. The lowest one leads and writes the ephemeral /GZFAS/leader. Each other server watches the server before it. When the leader falls, the next one leads.
